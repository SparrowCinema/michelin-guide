# 米其林全球名录

全球约 2 万家米其林餐厅的中文名录：三星、二星、一星、必比登推介和入选餐厅。

网址：https://sparrowcinema.github.io/michelin-guide/

|---|---|---|---|---|---|
| 161 | 544 | 3,175 | 3,744 | 12,097 | 19,721 |

## 能做什么

- **手机 App 版**：手机上底部有“名录 / 地图 / 附近 / 我的”四个标签，筛选条件收进底部弹出的面板。可以“添加到主屏幕”，从桌面图标全屏打开；页面和数据会缓存，没网也能查名录（地图除外）。
- **我的**：想去、去过两份清单，按最近标记、按地区或按自己的评分排列；统计去过的国家、城市和星级；可以导出、导入清单备份，切换浅色/深色主题。
- **筛选**：按等级、大洲、国家、城市逐级筛选，也可以搜店名、城市或菜系。“更多筛选”里还有菜系、价位、绿星、本版新上榜、今年升级、也上了黑珍珠。
- **地图**：切到“地图”查看当前筛选结果的分布，地图下方列出当前范围内的餐厅。中国境内用高德底图，其他地区用 Esri 街道图（加载失败时自动改用 OpenStreetMap）。
- **离我最近**：允许定位后，按离你的距离排序。
- **分享筛选结果**：筛选条件会写进网址，点“复制筛选链接”发给别人，对方打开看到的是同样的结果。
- **每家店**：中文店名、菜系、价位，以及米其林介绍页、地图（中国内地用高德，其他地区用谷歌地图）、餐厅官网的链接，还有“想去”“去过”和“纠错”按钮。点“去过”会弹出同一张卡片：半星评分、用餐日期（默认留空，可自选）、笔记，保存后即标记去过，按钮显示为“去过 ★4.5”；再点可新增、修改或删除独立的一次用餐，每次单独保存日期、评分和笔记。
- **标签**：新上榜、新摘星、升星、连续 N 年同一等级、绿星、黑珍珠钻级。
- **说明页**：讲清各等级的含义、米其林怎么评，以及黑珍珠是什么。

## 数据来源

- 餐厅名单、等级、地址、坐标、官网：米其林指南官网的公开数据，经开源项目 [michelin-my-maps](https://github.com/ngshiheng/michelin-my-maps) 汇总，这一版取自 2026 年 10 月 3 日的名单版本。
- 官方中文名：米其林指南中文官网（简体、香港繁体、台湾繁体版）。其他国家星级餐厅的“译名”是参考译名。
- 历年记录：michelin-my-maps 每年一份的历史名单版本（2022 至 2025 年，各取一份完整的），和当前名单逐家对比。
- 黑珍珠：2026 黑珍珠餐厅指南的公开报道和名单，只对照了中国内地、而且必须是同一家分店。二钻、三钻是完整的；一钻没有公开的完整名单，目前只覆盖了杭州、深圳的完整名单、全国新上榜的店和报道里提到的店。
- 各国指南发布时间不同，米其林也会随时撤下歇业的店，去之前请在米其林指南 App 核对。

## 文件

- `index.html`：页面。需要和 `data.json` 放在同一目录，经网页服务器打开（例如 GitHub Pages）。地图组件 Leaflet 在第一次打开地图时从 cdnjs 载入，失败时依次改用 jsDelivr、unpkg。
- `data.json`：全部餐厅数据。
- `og.png`、`icon.svg`、`icon-192.png`、`icon-512.png`、`icon-maskable.png`、`apple-touch-icon.png`：分享卡片图和图标。
- `manifest.webmanifest`、`sw.js`：添加到主屏幕所需的应用信息，以及离线缓存。
- `tools/build.py`：从 michelin-my-maps 的 CSV 生成 `data.json`，用法见文件开头。
- `tools/history.py`：从历年名单版本生成 `tools/history.json`（每家店每年的等级）。
- `tools/zh_official_names.json`：米其林中文官网的官方中文名（按米其林网址里的餐厅标识对应）。
- `tools/reference_translations.tsv`：星级餐厅的参考译名。
- `tools/cn_mainland_curated.json`：中国内地各指南发布时的中文名单，用来标出本版新上榜的餐厅。
- `tools/black_pearl_2026.json`：能对上米其林的 2026 黑珍珠餐厅（米其林网址 → 钻级）。

## 更新数据

```sh
# 1. 取最新的 michelin_my_maps.csv，以及一年前的名单版本（用 git 历史）
# 2. 生成历年记录
python3 tools/history.py michelin_my_maps.csv tools/history.json snap2022.csv snap2023.csv snap2024.csv snap2025.csv
# 3. 生成 data.json
python3 tools/build.py michelin_my_maps.csv tools/cn_mainland_curated.json data.json \
    tools/zh_official_names.json tools/reference_translations.tsv \
    tools/history.json tools/black_pearl_2026.json 2026-10-03
```

## 旅行指南功能（首版）

保留「名录 / 地图 / 附近 / 我的」导航：

- **旅行清单**：在「我的」创建和重命名旅行，在每家餐厅下点「加入旅行」多选分组；清单按城市展示，可按整份旅行或单个旅行城市在地图上查看。分组独立于「想去 / 去过」，删除旅行不会删除收藏和笔记。
- **餐厅档案**：点店名打开详情。`?restaurant=米其林路径` 可分享并直接打开，“去过 · 我的评分”与列表里的“去过”是同一份记录（日期、评分、笔记），另有逐年名单版本记录。静态托管下这不是单独生成的 SEO 页面。
- **美食护照**：根据本设备的「去过」统计国家、城市和餐厅，保留资料页与到访签章展示，不提供足迹地图。评级按当前数据，不推断到访年份的星级。
- **搜索**：中英文城市 / 菜系别名、混合关键词、重音归一；没有精确结果时，支持较长拉丁单词的一次编辑或相邻字母交换。不会对短词或汉字进行随意纠错。
- **参考价格**：`prices.json` 按固定餐厅 ID 保存官方菜单参考价、币种、餐别、计价口径、费用说明、来源和核实日期。初始仅覆盖 Arpège 与 Geranium 两家，不是全球人均价格库。具体价格仅在对应餐厅详情中展示；覆盖不足的预算筛选已移除，旧预算链接不会再隐藏其他餐厅。
- **星级变化**：比较 2025 年 10 月与当前名单版本的新增 / 升级星级，以及 2022–2026 连续五份名单版本三星。各地指南发布时间不一，不应称为完整官方年度名单。现有历史文件没有保存已移除餐厅的完整档案，暂不展示历史撤榜名单；缺失不代表停业。

个人数据仍保存在浏览器。v2 备份包含原有收藏、旅行和笔记，仍可导入旧 v1 收藏文件；合并时保留本机已有笔记。更换手机前请先导出。私人旅行 ID 和笔记不会写进分享链接。

## 数据检查与更新

- `python tools/check_updates.py --validate-only`：离线校验餐厅字段、稳定标识、坐标、历史编码及价格来源。
- `python tools/check_updates.py --candidate candidate.csv --out update-report.json`：比较候选 CSV，生成新增、移除、评级变化报告。
- 不传 `--candidate` 时，从 michelin-my-maps 的上游 CSV 获取候选。报告记录检查时间、候选 SHA-256、基准名单版本日期及被跳过的评级。
- GitHub Actions 的 **Check upstream data** 每周一 02:15 UTC（北京时间 10:15）检查一次，也可手动运行。报告保留为 30 天的工作流附件，并列出摘要；不会自动覆盖 `data.json` 或绕过 PR。
- 更新名单仍需人工核实候选差异，按原流程重建、修改 `DATA_VER`，通过 PR 发布；更新价格需核对官方来源和日期。暂未自动抓取官方菜单。
- **Validate guide** 在 PR 和 main 提交时执行数据与逻辑检查。只有实际成功运行后，才应把该检查加入仓库必需状态检查。
- `sw.js` 的 v10 更新保留旧版已缓存数据，补充新脚本的离线缓存，不清除收藏。地图底图和 Leaflet 仍需联网。

```sh
node --test tests/core.test.js
python -m unittest discover -s tests -p 'test_*.py'
python tools/check_updates.py --validate-only
```

数据更新：`.github/workflows/update-data.yml` 每周一自动运行——先读米其林官网发布会文章，把新发布的指南版本（指南年份＋实际发布日期）记进 `tools/editions.json`；再拉取上游名单，有变化就重建 `data.json`、写入本次按指南分组的变化（`updates.json`，首页顶部「本次更新」显示）并开 PR（需在 Settings → Actions → General 勾选 “Allow GitHub Actions to create and approve pull requests”）。也可在 Actions 页手动运行。

可选浏览器回归：安装 Playwright 与 Leaflet 后，运行 `node tests/browser.cjs`。覆盖移动端 / 桌面、旅行、分享链接、笔记、v1/v2 备份、预算、星级筛选，以及 旧版 → 当前版 离线缓存迁移。测试使用本地 Leaflet 和占位底图，不依赖地图供应商网络；真实 iPhone Safari 与外部底图连通性仍需设备验证。

本次更新与指南版本回归：`node tests/updates.cjs`；`python3 -m unittest tests.test_editions`。

云端同步回归：`node tests/sync.cjs`（两个浏览器档案模拟手机和电脑，经与 SQL 函数同契约的替身 API 同步；后端见 `supabase/`）。

英文界面回归：`node tests/english.cjs`（以 ?lang=en 逐页打开，残留中文即失败；用户自己的文字和官方中文地址除外）。

旅行路线回归：`node tests/route.cjs`（城市切换、跳过去过、按天拆分、导航链接、从我的位置出发、复制行程）。

用餐照片回归：`node tests/photos.cjs`。覆盖添加 / 压缩（≤1600px JPEG + 缩略图）、每次最多 9 张、封面、卡片 +N、全屏查看与左右滑动、删除后 IndexedDB 清理、取消清理、刷新保留，以及含照片的备份导出 / 导入。

### 护照册 UI

「我的美食护照」以酒红皮纹封面、金色纹样和纸质内页呈现。轻触或向左滑动封面翻开；手机和桌面均同时显示资料页与签章页，左右滑动或按钮翻页，包含立体翻页效果，遵从减少动态效果设置。按到访国家 / 地区生成签章，每页四枚，可翻页；签章仅展示到访记录，不再提供地图跳转。签章上的日期仅使用已填写的用餐日期，没有日期时显示“已记录”。打开状态仅保留在当前页面，不写入个人备份。

### 旅行美食地图

地图规划统一以旅行清单为单位。在「我的 → 旅行美食地图」创建旅行，在餐厅下点「加入旅行」收藏；餐厅按所在城市自动分组。可查看整份旅行地图，或点城市标签只查看该城市；地图上方可切换旅行和城市，也可直接创建新旅行。地图包含该旅行的全部餐厅，不限于已去过。护照的足迹地图入口与相关过滤已移除，原有收藏、笔记、旅行和护照签章保留。

地图默认作为预览：单指滑动或鼠标滚轮继续浏览页面，不会被地图截住。点「移动地图」后可拖动、双指缩放，点「完成移动」恢复页面滑动；滚轮始终用于翻页，地图可用加减按钮缩放。「查看餐厅」直接定位到下方清单，「显示全部筛选餐厅」恢复当前清单的地图范围。高分屏按 Retina 模式加载更精细的底图；筛选结果不超过 80 家时显示编号标记，与下方餐厅逐一对应。地图范围变化时，清单及数量一起更新。餐厅详情仍保留标题的阅读焦点，但不显示标题边框；按钮和表单的键盘焦点提示保留。缓存版本更新为 v13，个人收藏和旅行数据不变。

界面将技术性的版本说明收至「关于」；星级变化与预算位于更多筛选，历史评级只展示已有记录的年份。餐厅详情支持在顶部向下滑动关闭，评分为五颗星，支持半星与键盘方向键调整；半星评分同样随 v2 备份保存。


### 简洁名录与用餐记录

首页默认只展示搜索、评级和导航；地区、城市、菜系收进筛选，统计默认折叠。餐厅列表保留想去、去过、导航，加入旅行、官网、米其林来源与复制链接在详情中操作。

用餐记录统一为草稿→保存：清除评分、取消去过、修改日期与笔记均先在当前表单修改，点「保存记录」才生效。取消去过会同时清空评分与日期，笔记保留；可点「标记去过」重新记录。日期默认留空，可自选实际用餐日期或点「今天」，不再把收藏时间当作到访日期。保存成功会自动关闭并提示；两份存储一起写入，失败会回滚。旧备份结构与整数、半星评分保持兼容。

详情的历年评级与用餐表单默认展开；顶部拖动条始终可见，在任何阅读位置短下滑即可关闭。正文向下阅读仍保留滚动，不会因为上滑阅读被关闭。

### 个人旅行分享卡

「我的美食护照 → 分享我的美食护照」或具体旅行的「分享护照」，可选择全部到访／一趟旅行、用餐日期范围和卡片标题。只包含确实标为「去过」的餐厅、实际填写的日期及个人评分，不包含私人笔记；没有日期时不推断日期，按时间筛选时不把无日期记录纳入结果。每张最多四家，超过后分页，显示完整页数，每页可保存 1080×1620 PNG；支持文件分享的浏览器可打开系统分享面板。生成与导出均在本设备完成，离线也可使用。

分享卡使用本项目通过内置图像生成功能创作的纸感旅行插画 `assets/passport-share-art.webp`，提示词保存在 `assets/passport-share-art.txt`。背景仅作装饰；文字、数量、日期与评分全部由 `passport-share.js` 根据真实本机数据绘制。缓存与资源版本为 v15。

分享预览在没有到访记录或所选日期无结果时显示插画空状态，保存按钮保持禁用；不会用示例数据冒充个人记录。

### 弹窗背景滚动

打开餐厅、用餐记录、旅行或分享等弹窗前固定主页，并记住原来的滚动位置；弹窗内部可独立滚动。弹窗叠加时保持锁定，最后一层关闭后恢复页面位置和原有内联样式；关闭按钮、下拉、Escape 及程序关闭均使用相同行为。资源与缓存版本为 v16。


### 双页护照、地图分享与多次用餐（v17）

护照在所有屏幕上以完整双页平铺，封面可滑动打开，签章可左右滑动翻页，外部翻页按钮保留足够触控区域。分享入口位于护照标题下方，导出预览显示整张图片，底部固定保存按钮。分享卡按测量后的文本高度排版，英文按单词换行，插画只在独立页脚，不遮挡记录。

地图上方「分享地图与档案」及旅行清单「分享地图」可单独导出含底图、编号和餐厅档案的 PNG，包含尚未去过的计划餐厅，可选城市。宽度 1080 像素，按本页档案数量输出 1440／1680／1920 像素高度，每页最多三家。地图使用真实经纬度及 Esri 街道瓦片；跨日期变更线按最短经度范围取景。底图不可用时清楚标记为位置示意图，不冒充导航底图。地图生成需要联网；护照分享可离线使用。地图交互限制在世界边界，关闭世界无限重复。

餐厅详情与「去过」卡片支持「新增第 N 次用餐」，每次独立保存日期、半星评分、笔记，可单独修改或删除。默认编辑最近添加的一次，不会默默覆盖其他次数；取消本次用餐后仍保留其他到访，最后一次取消后才取消整家餐厅的去过。旧版单次记录按原内容保留，v2 备份在 records 下增加 visits 数组与稳定条目 ID，旧的汇总字段继续保留，导入合并按条目 ID 去重且本机内容优先。分享按实际用餐日期查历次到访，不包含私人笔记；护照统计仍按不同餐厅计数。


### 分享卡只画自己的足迹（v18）

两种分享图都只包含自己标记“去过”的餐厅，地图就是“我的足迹地图”：

- **护照卡片**：在资料统计和到访记录之间加了一张足迹地图。地图上所有去过的餐厅都有小圆点，本页列出的餐厅标出对应编号。高度 2052 像素，每页 4 家。
- **足迹地图与档案**：大地图加到访档案（地址、到访日期、次数、我的评分），每页 3 家。不再包含旅行清单里尚未去过的计划餐厅，也不再使用“地图当前范围”里的名录餐厅。
- 两种都可以按全部到访记录或单份旅行（只取其中去过的店）、城市、用餐日期范围筛选。私人笔记不会出现在图片中。
- 地图分享入口改名为“分享我的足迹地图”（地图上方）和“分享护照卡片 / 分享足迹地图”（旅行清单）。底图不可用或离线时，地图标注为位置示意图。


### 我的米其林结算地图与用餐时间线（v19）

**我的米其林结算地图**：取代原来的“护照卡片 / 足迹地图与档案”两种分享图，参照 IDF 观影结算，生成一整张长图，不分页：

- 深色抬头：标题（可改）、时间范围、国家和城市数。
- 四个数字：去过的餐厅、用餐次数、累计米其林星、我的平均分，下面是三星 / 二星 / 一星 / 必比登 / 入选各几家。
- 我的足迹地图：跨城市时每个城市一个圆点，数字是去过的家数，颜色取该城市最高等级；只有一个城市时逐家标编号。下方有等级图例。
- 这一路的高光：我的最高分、去得最多、星级最高或最近一次。
- 到访清单：按国家、城市分组，每家都有彩色等级标签（★★★ 三星 / ★★ 二星 / ★ 一星 / 必比登 / 入选）、菜系、用餐次数、最近日期和我的评分。
- 页脚：网站二维码（已解码验证）、麻雀映画 × Claude、网址和数据说明。
- 范围可选全部、今年、去年或自定义日期，也可只算某一份旅行里去过的店。只包含标记“去过”的餐厅，私人笔记不会出现在图中。图片太长时按比例缩小，以适应 iOS 的画布像素上限。
- 入口：“我的”页护照下方“生成我的米其林结算地图”，旅行卡片“生成这趟旅行的结算图”。地图页和旅行卡片上的地图分享入口已移除。

**餐厅页“我的用餐记录”**：

- 顶部摘要：用餐次数、平均评分、最近一次。
- 时间线：按日期从新到旧，每次用餐一张卡片，显示日期、半星评分和笔记摘要，点“修改”才在原位展开编辑。
- 同一时间只开一个编辑区，只有“删除这次 / 取消 / 保存”。删除需要点两次确认；删掉最后一次用餐，这家店自动取消“去过”。
- 在餐厅页里保存后，记录区保持打开，新卡片会短暂高亮；列表里的“去过”快捷卡片保存后自动关闭。
- 数据结构（records 下的 visits）与 v1/v2 备份不变。


### 城市日期签章（v21）
护照按实际到访城市与用餐日期分别盖章，同城同日合一章，不同日期独立保留。日期使用历次用餐记录，显示 DD MON YYYY 日期机字体，不推断今天。已配置地标的城市使用单色建筑版画，多个日期轮换当地不同地标；首批覆盖常见旅行城市，尚未配置地标的城市以城市字章显示，避免把通用建筑冒充当地地标。签章仅影响展示，不修改原有到访数据与备份。


### 中文参考地址（v22）
餐厅详情显示中文参考地址，可展开原文并复制中外文对照。中国内地提供高德入口，境外提供 Google 和 Apple 地图入口；地图链接不等于已通过地图核实地址或消费。

`address-localization.js` 在本机根据现有 19,721 条地址即时生成参考显示，保留原始地址及餐厅 ID。采用保守中文本地化：使用已有中文国家/城市名，翻译可确认的地区名、地址类型、常见酒店名、楼层及门牌单位；未确认的道路、建筑专名保留原拼写，不以拼音猜中文汉字。原文数字逐项检查；校验失败时保留完整原文及中文地区信息。生成方法为 `python tools/build_address_translations.py`，测试为 `python -m unittest discover -s tests -p 'test_*.py'`。这不是逐字完整机器翻译，也不是地图核验数据。原地址变化时按新原文即时生成，不缓存旧译文。

当前未配置高德 Web 服务或 Google Places 的可用凭证，未接入 POI 地址／消费查询，未新增人均消费数字。原来已核实菜单价格保留，不将相对价位 $ 换算为具体金额。翻译数据在首次加载后可离线使用，不影响个人收藏或备份。


### 餐厅官网照片背景（v24）
餐厅详情顶部以该餐厅的米其林指南图片作背景，标题有深色渐变遮罩，地址、评级与记录表单仍在清晰的页面底色上。图片来源链接返回对应米其林餐厅页，摄影版权归原权利人。图片从米其林 CDN 按需加载，不批量下载照片、不用其他餐厅或生成图补位。无匹配、图片失效或离线时保留纯色标题区与完整操作；异步图片不会重建表单或覆盖未保存草稿。

`photos/country-*.json` 按国家拆分，首次打开对应国家餐厅时才获取索引。索引优先按完整米其林餐厅网址匹配；城市网址变更仅在店名、餐厅 slug 一致、坐标相距100米以内且候选唯一时匹配，并在 manifest 中记录证据；不单凭店名猜测。校验图片仅指向米其林官方图片 CDN。基础图片网址来自 abobabo91/michelin-map 对米其林餐厅页 JSON-LD 的导出，补充官网原页画廊链接记录在 `tools/photo_supplement.json`；索引构建用 `python tools/build_photos.py --csv /path/to/michelin_all.csv`，覆盖情况及未匹配餐厅见 `photos/manifest.json`。匹配成功不代表每张图片已逐一联网验证可用；图片是否仍可加载由页面处理。该索引不改变星级、地址、餐厅 ID 或个人记录。

当前索引：19,522 / 19,721 家；199 家仍保留无图布局。三轮补查官网图库共补录519条图片链接，12家因城市路径变更按严格地理条件核对；覆盖数字以 manifest 为准。第二轮新增212家，第三轮直接打开249家英文实时页面的公开图库，再补回50家。第三轮同时记录195家使用官网通用占位图，4家未取得图片（其中 New Mandarin Seafood Restaurant 的 Global English 页面显示 Restaurant not found）；详情及名单见 `tools/photo_supplement.json` 的 `english_review`。不会用通用占位图冒充该餐厅照片。

第二、三轮新增照片均在2026-10-27请求实际页面所用的1200×800图片网址，确认HTTP 200、图片可解码及尺寸有效；来源页面、图库标题和检查结果记录在 `evidence` 中。此检查只代表当时可用，不保证外站未来状态。图片索引按需读取，图片文件不纳入离线预缓存。
